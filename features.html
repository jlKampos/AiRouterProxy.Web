Everything in the box

A complete local gateway. No databases, no dashboards to host — a single Windows service with hot-reloadable config.

✧Multi-vendor redaction

Formats validated against the canonical gitleaks rules: OpenAI sk-…, Anthropic, GitHub ghp_/github_pat_, AWS (real base32 keys), Google AIza/ya29., GitLab, DigitalOcean, Hugging Face, Replicate, PyPI, Docker Hub, Discord, Twilio, SendGrid, Mailgun, Shopify, Azure, DB URLs…

◈Fixed mask

The mask is always 6 bullets — it never reveals the real length of the secret, so an attacker learns nothing about format or size.

◎Fail-closed inspection

415 / 400 / 413 for anything that isn’t clean, inspectable JSON. Uninspected bodies never leave the machine.

⚿Multi-key auth

LocalKey or LocalKeys[] — case-sensitive, literal values, empty keys rejected. Perfect for rotation and per-person keys.

⇄Longest-prefix routing

Segment-safe route matching with per-route keys. No traversal, no %2f bypasses.

↯Rate limit + lockout

429 with Retry-After, per-IP windows, and a brute-force lockout. Thread-safe and covered by concurrency tests.

≋SSE adapters

OpenAI chat, OpenAI responses, Anthropic and a generic fallback — protocol-aware streaming end to end.

☰Admin surface

/admin/health, /admin/endpoints, /admin/activity, /admin/refusals, /admin/logs — every response masks secrets.

↻Hot-reload config

routes.json + redaction.json live in config\ and reload without restarting the service.

Redaction layers (in one pass)

Field names

api_key, password, token, senha… — only the value is masked. Matching is convention-agnostic: ApiKey/API_KEY/api-key/apikey are all caught, plus the auth/session/id token and JWT/signing-key families. A *_tokens family is excluded so usage counters like max_tokens are never touched.

Known vendor formats

Everything in the list above, plus JWT, Bearer <value>, PEM private key blocks and URL-embedded credentials (scheme://user:pass@…).

Key: value context

Config excerpts pasted into messages — "LocalKey": "abc…" or aws_secret_access_key=… — with safe delimiters so connection strings don’t swallow the next key. Context detection is also convention-agnostic (AuthToken, session-token, jwt_key…).

Long high-entropy tokens

Optional (configurable) layer for URL-safe tokens ≥ 28 chars that look random — with an allow list to keep file names and IDs readable.

Exemptions never apply to known formats. Whatever the config says, sk-…, ghp_, AIza…, JWT, Bearer and PEM are always masked. Image/binary payloads (data:…;base64,…) pass through untouched so vision payloads are never corrupted.
