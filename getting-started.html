Up and running in minutes

AiRouterProxy is a .NET 10 service. Build it self-contained, deploy the folder, point your agents at https://localhost:4000.

Publish self-contained

The target host has no x64 .NET runtime, so a framework-dependent publish fails to start. Always publish win-x64 self-contained:

# from the repo root
dotnet publish src/AiRouterProxy/AIRouterProxy.csproj -c Release -r win-x64 --self-contained true -o publish-tmp

Deploy (Windows Service)

The deploy script stops the service, copies the build, preserves your config/certs and starts the service again — needs elevation once:

powershell -ExecutionPolicy Bypass -File .\scripts\deploy-update.ps1 -DeployDir "C:\Services\AiRouterProxy"

Config lives in a config\ subfolder next to the exe (appsettings.json, routes.json, redaction.json, TLS certs).

Verify with your local key

$ curl -k https://localhost:4000/admin/health -H "Authorization: Bearer <LocalKey>"
# {"status":"ok","version":"2.3.0","uptimeSec":…}

Point your agents at it

# any OpenAI-compatible client
base_url = "https://localhost:4000/v1"
api_key  = "<LocalKey>"

# or route to OpenRouter on demand
base_url = "https://localhost:4000/openrouter/v1"

Config in one place

# routes.json  (hot-reload)
{ "Routes": [
  { "Prefix": "",
    "BaseUrl": "https://api.airouter.ch",
    "KeyRef": "" },
  { "Prefix": "/openrouter",
    "BaseUrl": "https://openrouter.ai/api",
    "KeyRef": "OPENROUTER" }
]}

# redaction.json  (hot-reload) — disable the noisy
# layer, never the known-format one
{ "detect": { "byLongStrings": false } }

Quality gates

Unit harness (offline)

dotnet run --project tests/Unit/RedactorTests.csproj -c Release → 287 PASS / 0 FAIL

Integration (black box, real proxy + AI Router)

dotnet run --project tests/Integration/Integration.csproj -c Release -- --key-file <key> → 24 PASS / 0 FAIL

Perf (optional)

--perf — p50 TTFT ≈ 586 ms (DeepSeek-V4-Flash), ≈ 45 ms (Qwen3.8).

Keep config on the server. appsettings.Server.json, TLS certs and the local key live only on the deployed machine — never in the repo. The deploy script preserves them across updates; after a deploy, restore the live redaction.json if you keep internal allow prefixes.
