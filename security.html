Security principles

The proxy is designed around a simple bias: if it can’t prove something is safe, it doesn’t happen.

✕Keys are never logged

Refusals write to the event log as PresentedLen · PresentedHash · ExpectedHash · KeyCount · UA — hashes and lengths only, never the value itself.

◈Fixed-length mask

Six bullets for every secret, regardless of length. The structure of your JSON is preserved; the shape of your secrets is not revealed.

◎Fail-closed by default

Uninspectable bodies never go upstream. The safe answer to “I don’t know” is 415/400, not “maybe pass it”.

◈Admin never leaks

/admin/endpoints shows the redaction state as bullets. Activity and logs never echo key material. The mask itself is never returned as a real value.

↯Brute-force lockout

10 failures in the window locks the source IP for 5 minutes — even correct keys are refused during lockout, so scanners can’t grind through your key space.

▣Images are exempt

Base64 image payloads (image_url.url, Anthropic source.data) pass through untouched — scanning them would corrupt the model’s input. Known formats next to images are still masked.

↻Deploy-safe config

Secrets live only on the server (appsettings.Server.json, certs, local key). The repo carries neutral examples; deploy-update.ps1 preserves what’s already installed.

⚿TLS for local traffic

HTTPS on :4000 even locally, via a PKCS12 round-trip that keeps Schannel happy. Integration tests pin against the self-signed cert deliberately.
